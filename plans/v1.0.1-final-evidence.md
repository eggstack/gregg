## Phase 32 and 33 corrections implemented locally

The following Phase 31 release-control corrections remain in place. The Phase
32 pass additionally centralizes sustained evidence validation, positively
joins scheduler shutdown, adds explicit cross-run manifest scope and artifact
identity, accepts immutable external selection input, validates a true 1.0.0
disposition, binds provenance to declared files, and adds package-specific
Boundary-2 re-verification stages. GitHub-hosted qualification is recorded
below; final release evidence remains outstanding.

- **Machine-readable dispatch contract**: `plans/evidence/release-dispatch-contract.json`
  defines, for each `workflow_dispatch.stage`, the reachable producer jobs,
  required logical stages, mode classification, and whether a prior publication
  is required.
- **Dispatch-local aggregation**: The `aggregate` job in `release-candidate.yml`
  now reads required stages from the dispatch contract instead of a hardcoded
  `case` statement. `mixed-fleet-client` requires only `source-ci` and
  `mixed-fleet-functional`; `mixed-fleet-sustained` requires only `source-ci`
  and `mixed-fleet-sustained`.
- **Workflow validator enhanced**: `scripts/validate-release-workflow.py` now
  loads and validates the dispatch contract against workflow dispatch options
  and the requirements contract.
- **Run-selection normalization**: `plans/evidence/v1.0.1-run-selection.example.json`
  uses exact logical stage names (`binary-prepublish-greggd`,
  `binary-prepublish-gregg`, `binary-msrv-greggd`, `binary-msrv-gregg`) instead
  of grouped aliases. Selection validation rejects grouped aliases.
- **Stage-to-artifact binding**: `scripts/github-artifact-retrieval.py` binds
  each logical stage to exactly one containing artifact instead of attaching
  all artifacts from a run to every stage.
- **Provenance indexing by document content**: Package provenance is indexed by
  reading `package-provenance.json` document keys instead of inferring from
  stage names.
- **Boundary-aware requirements**: `plans/evidence/release-requirements.json`
  now includes `candidate_required_stages` and
  `protocol_publication_required_stages` alongside the existing
  `pre_tag_required_stages` and `final_required_stages`.
- **Sustained summary semantics**: The sustained workload runner now validates
  `requested_duration_secs` equals configured value, `completed_generations >= 2`,
  generation range consistency, `online_results > 0`, `offline_results > 0`,
  nonempty transitions, `clean_shutdown == true`, `panic_or_join_failure == null`,
  and observed concurrency is positive and within configured limits.
- **Positive shutdown observation**: The sustained workload test now drains
  the scheduler channel after cancellation with a bounded deadline, recording
  `clean_shutdown: true` only after the scheduler task completes.
- **Sustained summary fields split**: `max_concurrent_polls` is split into
  `configured_max_concurrent_polls` and `observed_max_concurrent_polls`.
