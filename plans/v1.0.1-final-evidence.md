## Phase 18 corrections implemented

The following Phase 18 orchestration corrections have been committed:

- **Per-run artifact selection**: `plans/evidence/v1.0.1-run-selection.example.json`
  now declares artifact expectations per selected run, not a global list. Each
  run entry contains `run_id`, `attempt`, `workflow_name`, and an `artifacts`
  array with exact artifact names and optional explicit numeric IDs.
- **Selection validation**: `scripts/github-artifact-retrieval.py` validates
  the selection schema before any network access: candidate SHA format,
  release version (1.0.1), tooling SHA format, nonempty runs, numeric
  run IDs/attempts, nonempty artifact names, no duplicate names, no
  unsupported workflow names, and valid mode (pre-tag/final).
- **End-to-end artifact retrieval**: `main()` now calls `download_artifact()`
  for every selected artifact. Each downloaded ZIP receives a SHA-256, byte
  size, safe extraction, and validation of all contained candidate.json files.
- **Safe ZIP extraction**: `_safe_extract_zip()` rejects absolute paths,
  `..` traversal, entries resolving outside the extraction root, colliding
  normalized names, empty archives, and archives exceeding entry/size limits.
- **All candidates validated**: Every `candidate.json` inside every artifact
  is validated against expected SHA and version. Mixed SHAs or versions fail.
- **Retrieval manifest consumed by aggregation**: `--retrieved-manifest`
  argument propagates numeric artifact IDs and ZIP digests into the final
  manifest via `github_artifact` entries on each stage.
- **GitHub artifact identity vs content artifacts**: Stage entries now carry
  `github_artifact` (numeric ID, name, ZIP SHA-256, ZIP size) separately
  from `content_artifacts` (semantic content roles).
- **Pre-tag/final mode separation**: `release-requirements.json` defines
  `pre_tag_required_stages` and `final_required_stages`. The aggregation
  script accepts `--mode pre-tag` or `--mode final`. Pre-tag mode does not
  require tag, registry, disposition, or postpublish evidence.
- **Package-native dispatch repair**: `native-package-evidence` no longer
  requires `binary-prepublish` to succeed in the same dispatch. It downloads
  artifacts from the selected `package_run_id`/`package_run_attempt` into
  separate `package-artifact/greggd/` and `package-artifact/gregg/` roots.
  Each package uses its own provenance and lockfile.
- **Mixed-fleet-sustained stage**: A distinct `mixed-fleet-sustained` job
  exercises the production state engine, scheduler, and poller across
  multiple generation cycles. The stage is included in both pre-tag and
  final mandatory stage sets.
- **Protected cleanup fails closed**: `systemd-lifecycle` and
  `launchd-lifecycle` cleanup steps no longer use `|| true`. Both jobs
  use explicit step IDs and a final verdict step that fails if either
  gate or cleanup failed.
- **Immutable finalizer tooling**: `release-finalize.yml` checks out the
  candidate SHA, verifies `git rev-parse HEAD` matches, and records
  `tooling_sha` in the manifest. Mutable default-branch checkout is
  prohibited.
- **Evidence bookkeeping corrected**: This ledger now records the correct
  Phase 17 substantive implementation commit SHA separately from the
  fixture-correction commits. Ordinary CI and frozen release evidence are
  clearly separated.

## Blockers

The release cannot honestly be marked complete from this checkout. The remaining
gates require infrastructure not available locally:

1. Freeze a clean candidate after the final local checks and record its full SHA.
2. Run the staged workflow against that SHA, retaining run IDs, attempts, artifact names/IDs, package checksums/sizes, normalized manifests, and candidate metadata.
3. Execute protected systemd/launchd and resource/soak gates on trusted native hosts.
4. Decide the `1.0.0` disposition before publication.
5. Create and verify the annotated tag, publish in dependency order, and run the postpublication registry-install workflow.
6. Replace this ledger with immutable results only after all mandatory gates pass; then update `plans/README.md` and the plan status.
