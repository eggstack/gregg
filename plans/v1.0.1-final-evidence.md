## Corrective implementation status

Completed in the working tree and requiring final source-CI confirmation:

- `verify-installed-daemon.sh` writes the flat `greggd` configuration schema,
  requires `curl`, `jq`, and `python3`, distinguishes connection/warming/
  malformed responses, validates protocol bounds, and checks the reaped child
  exit status.
- Package installation is explicit in the staged release workflow. The
  verifier receives the installed path and never falls back to a workspace
  binary.
- Client atomic and editor temporary files are created with Unix mode `0600`
  before configuration bytes are written. Required permission failures are
  returned as `ConfigError::AtomicWrite`.
- Launchd state transitions execute through a narrow injectable command runner;
  fake-runner tests cover idempotency, state branches, exact arguments, and
  error propagation.
- Release workflow stages now separate protocol prepublication, indexed
  protocol verification, binary stable/MSRV verification, native evidence,
  protected operational evidence, and postpublication installs. Stage jobs
  upload candidate metadata and an aggregate job rejects mixed candidate SHAs.
- Resource and soak harnesses require explicit binaries, generate valid flat
  daemon configuration, fail on daemon/HTTP errors, and emit CSV/JSON output.

## Evidence rules

- A source-built smoke is labelled source-built and cannot satisfy a
  package-installed gate.
- A workflow definition is not runtime evidence. Every native, operational,
  soak, registry, and publication claim needs durable output tied to the final
  full candidate SHA.
- The tagged source commit and any later documentation-only evidence commit are
  distinct. Source, manifests, workflows, scripts, and packaging cannot change
  after the tag is created.
- If protocol publication succeeds and a later gate fails, the tag and partial
  registry state remain immutable; any source correction requires a new patch
  version.
