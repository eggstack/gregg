## Workstream A — launchd lifecycle correctness

### A1. Correct `launchctl bootstrap` syntax

`bootstrap()` now uses `domain_target()` (returns `"system"`) instead of
`service_target()` (returns `"system/com.eggstack.greggd"`).

| Criterion | Evidence |
|---|---|
| `bootstrap` uses domain target | `crates/greggd/src/service/launchd.rs`: `bootstrap_args()` returns `["bootstrap", "system", <plist-path>]` |
| `bootout` uses service target | `bootout_args()` returns `["bootout", "system/com.eggstack.greggd"]` |
| `kickstart` uses service target | `kickstart_args()` returns `["kickstart", "-k", "system/com.eggstack.greggd"]` |
| `print` uses service target | `print_args()` returns `["print", "system/com.eggstack.greggd"]` |
| Domain and service targets are separate | `domain_target()` and `service_target()` are distinct methods |

**Test result**: `cargo test -p greggd --lib -- service::launchd` — 24 passed, 0 failed.

| Criterion | Evidence |
|---|---|
| Lock covers full transaction | `edit_transaction()` calls `self.acquire_lock()` before editing |
| `EditorFailed` error variant | Added to `ConfigError` enum in `crates/gregg/src/config.rs` |
| CLI uses `edit_transaction` | `cmd_edit()` in `cli.rs` calls `store.edit_transaction()` |

### B2. Edit a temporary copy

| Criterion | Evidence |
|---|---|

| Parse and validate before commit | `edit_transaction()` parses and validates before atomic rename |
| Atomic replace via durable write path | `edit_transaction()` calls `write_atomic()` for the final commit |
| Temp cleanup on all paths | `edit_transaction()` removes temp in all branches |

## Handoff blockers

The following criteria cannot be satisfied on this Linux x86-64 machine and
require native hardware, service-manager privileges, soak duration, or
crates.io credentials:

1. **F1. Linux ARM64 native evidence** — Requires a native ARM64 Linux host or
   self-hosted GitHub Actions runner. Attempted command:
   `cargo test --workspace --all-targets --all-features` on ARM64 Linux.
   Environment needed: Linux ARM64 machine.

2. **F1. macOS Intel and Apple Silicon native evidence** — Requires macOS CI
   runners with native Mach/sysctl test execution. Environment needed: macOS
   machines (Intel and Apple Silicon).

3. **F3. Native systemd lifecycle** — Requires a real systemd Linux host with
   root or sudo access. Attempted command:
   `./packaging/install-linux.sh && systemctl start greggd`.
   Environment needed: Linux x86-64 or ARM64 with systemd.

4. **A4. Native launchd lifecycle** — Requires a real macOS host with launchd
   service-manager privileges. Attempted command:
   `greggd start && greggd stop && greggd start`.
   Environment needed: macOS machine (Intel or Apple Silicon) with root access.

5. **F4. Resource measurements** — Requires release binaries running on native
   hardware for 24-hour measurements. Script exists at
   `scripts/measure-resources.sh` but requires native execution.

6. **F5. 24-hour soak** — Requires running daemon and client soaks for 24 hours
   on Linux and macOS. Script exists at `scripts/soak-test.sh` but requires
   native execution over 24 hours.

7. **G3-G5. Freeze, tag, and publish** — Cannot freeze the candidate commit,
   create an annotated `v1.0.1` tag, or publish to crates.io without crates.io
   credentials and publication authorization.

8. **G4. `1.0.0` disposition** — Cannot decide yank/retention without reviewing
   the published `1.0.0` crates on crates.io.
