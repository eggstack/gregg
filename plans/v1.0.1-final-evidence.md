## Implementation status

### Implementation landed

The following Phase 17 implementation has been committed:

- **Cross-run evidence retrieval**: `scripts/github-artifact-retrieval.py`
  queries the GitHub Actions API for selected workflow runs and attempts,
  resolves actual numeric artifact identities, downloads artifact ZIP archives,
  calculates their SHA-256 and byte size, extracts them, and validates
  contained candidate metadata before consuming any other file. Deterministic
  tests cover failed-run rejection, wrong-attempt rejection, wrong-repo/workflow
  rejection, and valid-run acceptance.
- **Protected final aggregation**: `.github/workflows/release-finalize.yml`
  accepts a checked-in run-selection file, candidate SHA, release version, mode
  (pre-tag or final), and optional tag name. It uses `contents: read` and
  `actions: read` permissions and a protected environment.
- **Candidate metadata schema**: `plans/evidence/candidate.schema.json` now
  requires `source_identity_mode` (`pre-tag-full-sha` or `annotated-tag`),
  artifact entries carry `role`, optional `sha256`/`size_bytes`/`media_type`/`path`,
  and annotated-tag mode requires complete tagger and tag-object content metadata.
- **Tag timestamp normalization**: `scripts/verify-candidate-identity.sh`
  normalizes the tagger timestamp to canonical RFC3339 UTC ending in `Z` using
  Python, preserves the original timestamp as a diagnostic field, and validates
  tag metadata completeness (tag-object SHA, peeled commit SHA, tagger name/email,
  tag object content SHA-256, checked-out HEAD).
- **Lockfile reuse**: `scripts/install-verified-package.sh` now requires
  `--lockfile`, verifies the supplied lockfile checksum and size against
  provenance, rejects divergent existing lockfiles, copies the verified lockfile
  into the unpacked package, re-verifies the copied checksum, and never invokes
  `cargo generate-lockfile` in qualifying mode.
- **Package provenance**: `scripts/write-package-provenance.py` now accepts
  optional metadata fields (normalized manifest, package list, transcripts) and
  verification lockfile identity. `scripts/merge-package-provenance.py`
  deterministically merges protocol, daemon, and client provenance into one
  canonical three-crate manifest, rejecting missing, duplicate, mixed-SHA, and
  conflicting entries.
- **Native evidence split**: The existing native matrix is renamed to
  `native-source-*` stages. Four `native-package-*` matrix jobs install from
  verified `.crate` artifacts using verified lockfiles. `plans/evidence/release-requirements.json`
  reflects the approved split.
- **Mixed-fleet coverage**: The functional test now covers a
  healthy-to-failure transition in addition to failure-to-recovery.
- **Protected-host hardening**: `scripts/preflight-protected-host.sh` and
  `scripts/cleanup-protected-host.sh` provide preflight checks and guaranteed
  `if: always()` cleanup for systemd and launchd lifecycle jobs.
- **Artifact roles**: Candidate artifact entries use `role` fields
  (`package-archive`, `transcript`, `binary-checksums`, `daemon-verifier`,
  `lifecycle-transcript`, `preflight`, `cleanup`) instead of semantic
  `artifact_id` labels.

## Blockers

The release cannot honestly be marked complete from this Linux ARM64 checkout.
The remaining gates require infrastructure not available locally:

1. Freeze a clean candidate after the final local checks and record its full
   SHA.
2. Run the staged workflow against that SHA, retaining run IDs, attempts,
   artifact names/IDs, package checksums/sizes, normalized manifests, and
   candidate metadata.
3. Execute protected systemd/launchd and resource/soak gates on trusted native
   hosts (Linux x86-64, Linux ARM64, macOS Intel, macOS Apple Silicon).
4. Decide the `1.0.0` disposition before publication.
5. Create and verify the annotated tag, publish in dependency order, and run
   the postpublication registry-install workflow.
6. Replace this ledger with immutable results only after all mandatory gates
   pass; then update `plans/README.md` and the plan status.
