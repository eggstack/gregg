# Phase 25: `v1.0.1` endpoint and persisted-config correctness

## Objective

Create one canonical endpoint validation path used by both CLI parsing and persisted TOML, reject unsupported scoped IPv6 explicitly, validate endpoint identity, and guarantee that every accepted endpoint can be rendered into a syntactically valid poll URL.

## Baseline defects

At baseline `eab5fe2e1d8f4635bb09aaf4ba69e18375ff5671`:

1. `EndpointSpec::parse_bracketed_ipv6()` deliberately skips strict IP parsing to permit zone identifiers.
2. `normalize_host()` leaves any non-`IpAddr` input unchanged.
3. `status_url()` brackets a host only when `host.parse::<IpAddr>()` succeeds and the host contains a colon.
4. A scoped IPv6 host such as `fe80::1%en0` therefore fails `IpAddr` parsing and becomes an invalid unbracketed URL.
5. `Config::validate()` checks duplicate IDs but does not require IDs to be nonempty valid UUID v4 values.
6. Persisted hosts receive only a few substring checks and can bypass the CLI parser’s endpoint grammar.
7. Duplicate address detection occurs before canonical host validation and can disagree with actual endpoint equivalence.

## Release policy for scoped IPv6

For version `1.0.1`, **reject scoped/zone-qualified IPv6 endpoints** with a dedicated diagnostic.

Examples that must be rejected:

```text
[fe80::1%en0]:11310
[fe80::1%25en0]:11310
fe80::1%en0
```

Full scoped IPv6 support requires interface-scope representation and correct URI percent encoding. That is not necessary for the version-1 private-network contract and must not be partially implemented.

A future release may add explicit support with a structured scope identifier.

## Scope

### In scope

- `crates/gregg/src/endpoint.rs`;
- `crates/gregg/src/config.rs`;
- `crates/gregg/src/poller.rs`;
- CLI tests that create, list, remove, edit, or load endpoints;
- config examples and diagnostics.

### Out of scope

- DNS resolution changes;
- mDNS discovery;
- scoped IPv6 support;
- TLS URL construction;
- changing the persisted config version unless absolutely required;
- changing endpoint IDs for already valid entries automatically.

## Canonical host validator

Introduce one function or type that validates and normalizes a host without a port. Recommended shape:

```rust
pub fn parse_host(input: &str) -> Result<NormalizedHost, EndpointError>;

pub enum NormalizedHost {
    Ip(IpAddr),
    Dns(String),
}
```

A simpler string-returning function is acceptable when it still distinguishes IP and DNS validation internally.

### Host acceptance rules

Accept:

- IPv4 literals accepted by `std::net::IpAddr`;
- unscoped IPv6 literals accepted by `std::net::IpAddr`;
- ordinary DNS or mDNS hostnames used by the existing product, including `localhost` and names such as `server.local`.

Reject:

- empty or whitespace-only input;
- leading or trailing whitespace in persisted values;
- URL schemes;
- credentials or `@`;
- `/`, `?`, or `#` URL components;
- brackets in the stored host value;
- control characters;
- embedded ASCII whitespace;
- `%` zone/scope identifiers;
- a colon-containing value that is not a valid unscoped IPv6 literal;
- DNS labels that are empty or exceed documented bounds;
- a hostname exceeding the total documented bound.

Do not silently trim persisted hosts. Reject and identify the affected endpoint ID.

### DNS normalization

Use a consistent comparison key:

- IP literals: standard-library canonical string;
- DNS names: ASCII lowercase for equality and duplicate detection;
- display/persistence may preserve the original case only if every comparison uses the lowercase key.

Prefer canonical lowercase persistence for newly written configurations to reduce ambiguity. Do not rewrite existing files during a read-only load unless the existing edit flow already performs a canonical write.

## EndpointSpec changes

`EndpointSpec::parse()` must use the canonical host validator for every path:

- host without port;
- host with port;
- bare IPv6;
- bracketed IPv6.

For bracketed input:

1. require one closing bracket;
2. require nonempty content;
3. reject `%` scoped forms with a dedicated `EndpointError` variant;
4. require the bracket contents to parse as IPv6, not arbitrary text;
5. require `:<port>` after the bracket;
6. normalize the IPv6 literal.

Example new diagnostic:

```text
scoped IPv6 endpoints are not supported in config version 1: fe80::1%en0
```

## Poll URL construction

Remove the duplicated host classification in `status_url()`.

Preferred construction:

```rust
pub fn status_url(endpoint: &Endpoint) -> String {
    format!("http://{}/v1/status", endpoint.display_address())
}
```

If the function signature must remain `status_url(host, port)`, it must call the same canonical address formatter used by `Endpoint::display_address()`.

For every accepted endpoint:

- IPv4/DNS: `http://host:port/v1/status`;
- IPv6: `http://[addr]:port/v1/status`.

No accepted host may produce whitespace, an unescaped `%`, duplicate brackets, or an unbracketed IPv6 URL.

## Persisted ID validation

Every `SystemEntry.id` must:

1. be nonempty;
2. parse with `uuid::Uuid::parse_str`;
3. be version 4;
4. use canonical hyphenated lowercase representation, or be normalized before persistence;
5. be unique after canonicalization.

Add structured violations for:

- empty ID;
- malformed UUID;
- wrong UUID version;
- noncanonical UUID if the implementation rejects rather than normalizes it;
- duplicate canonical UUID.

Do not generate a replacement ID silently during load. A manually corrupted config must fail with an actionable error.

## Persisted host validation

In `Config::validate()`:

1. validate the ID;
2. validate and normalize the host with the shared host validator;
3. validate the port;
4. construct the canonical address key;
5. perform duplicate-address detection on that key;
6. validate the optional name.

Do not use `format!("{}:{}", host.to_lowercase(), port)` before proving the host is valid.

`SystemEntry::to_endpoint()` may remain infallible only because `Config::parse()` and mutation paths validate first. Add a debug assertion or test that invalid entries cannot reach polling through normal APIs.

## Configuration mutation paths

Every path that adds or edits an endpoint must:

- parse through `EndpointSpec`;
- produce a UUID v4;
- validate the complete resulting `Config` before writing;
- preserve atomic and permission-safe write behavior;
- reject a duplicate canonical address even when the input spelling differs.

Examples that must collide:

```text
SERVER.LOCAL:11310
server.local:11310
```

```text
[0:0:0:0:0:0:0:1]:11310
[::1]:11310
```

## Required tests

### Endpoint parser tests

Positive:

1. IPv4 with default and explicit port;
2. DNS and mDNS hostnames;
3. bare unscoped IPv6 with default port;
4. bracketed unscoped IPv6 with explicit port;
5. canonical IPv6 normalization;
6. case-insensitive DNS equality.

Negative:

1. `%en0` scoped IPv6;
2. `%25en0` URL-encoded scoped IPv6;
3. bracketed arbitrary text;
4. malformed bracket suffix;
5. embedded whitespace;
6. scheme, path, query, fragment, and credentials;
7. colon-containing non-IPv6 input;
8. empty DNS label;
9. overlong label and overlong host.

### URL tests

1. accepted IPv4 URL exact match;
2. accepted DNS URL exact match;
3. accepted IPv6 URL is bracketed;
4. every accepted endpoint’s URL parses with the HTTP client’s URL parser;
5. no accepted endpoint produces a raw `%` scope marker;
6. invalid host cannot reach `status_url()` through config load.

### Config tests

1. valid canonical UUID v4 accepted;
2. empty ID rejected;
3. malformed UUID rejected;
4. UUID v1/v3/v5 rejected;
5. duplicate UUID with case differences rejected;
6. invalid persisted host rejected;
7. scoped IPv6 persisted host rejected;
8. duplicate DNS address with case differences rejected;
9. duplicate equivalent IPv6 spellings rejected;
10. original config remains unchanged after failed edit validation;
11. valid manually edited TOML loads and polls;
12. invalid manually edited TOML reports all relevant violations.

## Smaller-model implementation sequence

1. Add a dedicated scoped-IPv6 error variant.
2. Add failing endpoint and URL tests.
3. Extract the canonical host validator.
4. Route all parser branches through it.
5. Route URL formatting through `Endpoint::display_address()` or one shared helper.
6. Add UUID validation to `Config::validate()`.
7. Reorder canonical address duplicate checks after host validation.
8. Add persisted TOML tests.
9. Run CLI mutation tests.
10. Run the complete workspace gate.

## Guardrails

- Do not add partial scoped IPv6 encoding.
- Do not accept arbitrary bracket contents.
- Do not silently replace invalid persisted UUIDs.
- Do not introduce a second host validator in config.
- Do not rely on reqwest to reject malformed URLs after config has loaded.
- Do not weaken atomic-write or permission tests.
- Do not change daemon bind-address parsing in this phase.
- Do not add a URL parsing dependency unless the existing reqwest/url dependency cannot be reused internally.

## Acceptance criteria

Phase 25 is complete only when all criteria are demonstrated:

1. CLI and persisted TOML use one canonical host validator.
2. Scoped IPv6 is rejected explicitly in config version 1.
3. Bracketed input must contain a valid unscoped IPv6 literal.
4. Every accepted IPv6 endpoint produces a bracketed status URL.
5. Every accepted endpoint URL parses successfully before polling.
6. No accepted endpoint can produce an unbracketed colon-containing URL.
7. Persisted endpoint IDs must be canonical UUID v4 values.
8. Invalid IDs fail load with structured diagnostics.
9. Duplicate addresses are detected after canonical normalization.
10. Equivalent IPv6 spellings collide.
11. DNS comparison is case-insensitive.
12. Invalid manually edited TOML cannot reach the poller.
13. Failed edits preserve the original config.
14. Existing valid config and CLI behavior remain compatible.
15. Endpoint, config, poller, CLI, and workspace tests pass.
