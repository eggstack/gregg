# Phase 19 – Final Orchestration Integration Closure

## Scope

This phase is intentionally limited to the remaining end-to-end orchestration defects discovered after Phase 18.

## Work items

1. Authentication
- Make the retrieval CLI consume GITHUB_TOKEN automatically when --token is omitted.
- Add integration tests covering authenticated retrieval.

Acceptance criteria:
- Finalizer succeeds without explicitly passing --token.
- Missing credentials fail with a clear diagnostic.

2. Selection schema
- Eliminate duplicate artifact-name assumptions.
- Represent multi-stage artifacts explicitly.

Acceptance criteria:
- Example selection validates.
- Every logical stage resolves to exactly one downloaded artifact.

3. Stage mapping
- Build stage lookup from candidate metadata inside downloaded artifacts.

Acceptance criteria:
- Every required logical stage receives numeric GitHub artifact ID, ZIP SHA-256, ZIP size, run ID, and attempt.

4. Provenance and registry materialization
- Materialize registry summary, disposition, and merged provenance deterministically.

Acceptance criteria:
- Final aggregation requires no filesystem heuristics.

5. Sustained fleet
- Replace nominal timing with measured duration and resource sampling.

Acceptance criteria:
- Runtime duration is measured and enforced.
- Resource evidence is recorded.

6. End-to-end integration
- Add a mocked GitHub integration test executing retrieval through final aggregation.

Acceptance criteria:
- Test downloads artifacts, builds retrieved manifest, aggregates successfully in pre-tag mode, and verifies expected failures in final mode until publication inputs are present.
