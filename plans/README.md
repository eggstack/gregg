# Gregg version-1 plan index

This directory contains the implementation roadmap and execution-ready plans for taking Gregg through a credible, crates.io-published version 1.

The plans are ordered by dependency. A later phase may begin early only where its interfaces are already frozen and doing so does not bypass an earlier acceptance gate.

`1.0.0` was published after the initial implementation attempt. Phases 11 through 19 corrected many application and release-integrity defects and established candidate metadata, package provenance, artifact retrieval, native/package-native stage concepts, protected-host tooling, mixed-fleet fixtures, and final aggregation machinery. A post-Phase-19 audit found remaining release blockers in workflow reachability, sustained evidence, macOS Mach counter signedness, sampler readiness/freshness, endpoint/config validation, macOS service privilege, native CI coverage, bounded hot paths, and cross-run finalization. Phase 20 remains the umbrella source of truth. Phases 21, 22, and 31 through 34 have substantial implementation and hosted release-control evidence but require the Phase 35 evidence-lineage and production-finalizer closure; Phases 23 through 29 implement the remaining product/platform corrections. Phase 30 freezes one candidate and executes the immutable `v1.0.1` release evidence chain only after Phases 23 through 29 and Phase 35 are complete.

## Completion rule

A plan is not complete merely because its implementation has landed. It is complete only when every acceptance criterion is demonstrated by tests, native CI, reproducible commands, or immutable external evidence appropriate to the target platform.

A plan may be marked `implemented` only after every acceptance criterion is satisfied with evidence in the tree or an immutable linked CI/release record. Mock coverage of isolated helpers, source inspection, workflow definitions, version bumps, reduced green CI, cross-compilation, local source-built smokes, shortened soaks, semantic artifact labels, console-only checksums, or compensating reasoning cannot substitute for executable stage reachability, actual GitHub artifact identity, package-specific provenance and lockfiles, native package execution, live sustained workload/resource evidence, fail-closed cleanup, nonroot macOS lifecycle evidence, four-architecture CI/MSRV, annotated tag identity, publication, or registry-install verification.

Phase 20 is complete only after phases 21 through 29 and phase 35 meet their explicit acceptance criteria and Phase 30 produces a final independently validated manifest and reconciled evidence ledger for one immutable candidate SHA. No candidate may be frozen, tagged, or published while a Phase 23-29 or Phase 35 release blocker remains open.

Any discovered scope expansion should be recorded as a post-version-1 idea unless it is necessary for correctness, safety, advertised architecture support, publishability, release integrity, or the explicit product contract in `README.md`.
