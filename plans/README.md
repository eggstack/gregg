# Gregg version-1 plan index

This directory contains the implementation roadmap and execution-ready plans for taking Gregg through a credible, crates.io-published version 1.

The plans are ordered by dependency. A later phase may begin early only where its interfaces are already frozen and doing so does not bypass an earlier acceptance gate.

`1.0.0` was published after the initial implementation attempt. Phases 11 through 16 corrected the known application defects and established strong release-integrity foundations: canonical evidence, immutable candidate validation, package provenance, package-derived protected jobs, qualifying resource/soak modes, and staged publication checks. The latest review found that Phase 16 implementation landed, but final closure still requires true cross-run artifact retrieval, actual GitHub artifact IDs, merged three-crate provenance, verified lockfile reuse, package-native evidence, sustained mixed-fleet execution, guaranteed protected-host cleanup, normalized tag evidence, and final release execution. Phase 17 implementation has landed; frozen-candidate execution, tag creation, publication, and immutable evidence reconciliation remain pending protected-host and registry access. The implementation adds cross-run artifact retrieval, merged three-crate provenance, verified lockfile reuse, package-native evidence, sustained mixed-fleet coverage, protected-host preflight and cleanup, normalized tag evidence, and a protected final aggregation workflow.

## Completion rule

A plan is not complete merely because its implementation has landed. It is complete only when all acceptance criteria are demonstrated by tests, CI, reproducible commands, or documented manual evidence appropriate to the target platform.

A plan may be marked `implemented` only after every acceptance criterion is satisfied with evidence in the tree or an immutable linked CI/release record. Mock coverage, source inspection, workflow definitions, version bumps, reduced green CI, cross-compilation, local source-built smokes, shortened soaks, semantic artifact labels, console-only checksums, or compensating reasoning cannot substitute for actual GitHub artifact identity, merged package/lockfile provenance, package-native execution, native service-manager evidence, resource/soak evidence, annotated tag identity, publication, or registry-install verification.

Phase 17 may be marked implemented only after one frozen source SHA passes all source-native, package-native, merged-provenance, verified-lockfile, sustained mixed-fleet, lifecycle, resource, qualifying-soak, complete-artifact, protected cross-run aggregate, annotated-tag, publication, and clean registry-install gates; annotated `v1.0.1` peels to that SHA; all three `1.0.1` crates are published and registry-verified; actual workflow run/attempt/artifact identities and artifact archive digests are preserved; and complete immutable evidence is reconciled in `plans/v1.0.1-final-evidence.md`.

Any discovered scope expansion should be recorded as a post-version-1 idea unless it is necessary for correctness, safety, publishability, release integrity, or the explicit product contract in `README.md`.
