# Gregg version-1 plan index

This directory contains the implementation roadmap and execution-ready plans for taking Gregg through a credible, crates.io-published version 1.

The plans are ordered by dependency. A later phase may begin early only where its interfaces are already frozen and doing so does not bypass an earlier acceptance gate.

`1.0.0` was published after the initial implementation attempt. Phases 11 through 17 corrected the known application defects and established strong release-integrity foundations: canonical candidate evidence, package provenance, verified lockfile installation, source-native and package-native stage concepts, protected-host preflight and cleanup tooling, deterministic mixed-fleet fixtures, GitHub artifact retrieval primitives, and protected final aggregation. The latest review found that the Phase 17 architecture landed but its executable connections remain defective: finalizer arguments do not parse, artifacts are not downloaded from the retrieval entry point, numeric artifact identities do not reach aggregation, pre-tag mode follows the final path, package-native jobs are unreachable and use inconsistent artifacts, the sustained mixed-fleet stage is absent, cleanup failures are masked, and finalizer tooling is not immutably identified. Phase 18 is the active source of truth for the narrow orchestration correction required before candidate freeze, protected execution, tagging, publication, and immutable evidence reconciliation.

## Completion rule

A plan is not complete merely because its implementation has landed. It is complete only when all acceptance criteria are demonstrated by tests, CI, reproducible commands, or documented manual evidence appropriate to the target platform.

A plan may be marked `implemented` only after every acceptance criterion is satisfied with evidence in the tree or an immutable linked CI/release record. Mock coverage of isolated helpers, source inspection, workflow definitions, version bumps, reduced green CI, cross-compilation, local source-built smokes, shortened soaks, semantic artifact labels, console-only checksums, or compensating reasoning cannot substitute for executable end-to-end artifact retrieval, actual GitHub artifact identity, package-specific provenance and lockfiles, reachable package-native execution, sustained mixed-fleet evidence, fail-closed cleanup, immutable finalizer tooling, native service-manager evidence, qualifying resource/soak evidence, annotated tag identity, publication, or registry-install verification.

Phase 18 may be marked implemented only after the finalizer command parses, selected artifacts are actually downloaded and safely extracted, every candidate record is validated, numeric GitHub artifact IDs and ZIP digests propagate into aggregation, pre-tag and final modes pass their distinct complete synthetic tests, package-native jobs are reachable with matching producer/consumer contracts and package-specific provenance/lockfiles, a `mixed-fleet-sustained` job exists and is aggregatable, protected cleanup fails closed, finalizer tooling identity is immutable, the complete local gate passes, and a nonpublishing orchestration dry run produces a valid pre-tag manifest and demonstrably rejects missing mandatory evidence. Phase 17 release execution may resume only after those criteria are met.

Any discovered scope expansion should be recorded as a post-version-1 idea unless it is necessary for correctness, safety, publishability, release integrity, or the explicit product contract in `README.md`.
