# Phase 27: `v1.0.1` four-architecture CI and MSRV closure

## Objective

Make ordinary CI execute the complete workspace on all four advertised native architectures, prevent cross-architecture cache contamination, and check target-specific code against the declared Rust 1.75 MSRV.

## Dependencies

Phases 23 through 26 must be implemented before this phase is marked complete so the new native lanes validate corrected code rather than merely exposing known failures.

## Baseline gaps

At baseline `eab5fe2e1d8f4635bb09aaf4ba69e18375ff5671`, `.github/workflows/ci.yml` includes:

- Ubuntu x86-64;
- macOS ARM64;
- macOS Intel x86-64.

It does not include Linux ARM64 in ordinary push/PR CI, even though Linux ARM64 is an advertised target and appears in release-oriented native workflows.

The MSRV job runs only on Ubuntu x86-64, so target-specific macOS code and Linux ARM64 code are not checked with Rust 1.75.

The cache key uses only `runner.os` plus the lockfile hash, allowing Intel and ARM macOS lanes to share the same cache namespace.

## Scope

### In scope

- `.github/workflows/ci.yml`;
- native test selection and architecture assertions;
- CI cache keys;
- MSRV matrix;
- documentation of the supported/verified target matrix;
- narrowly scoped test fixes that expose real architecture assumptions.

### Out of scope

- adding Windows;
- cross-compilation as a substitute for native execution;
- release candidate orchestration;
- performance optimization;
- lowering MSRV;
- skipping native collector tests.

## Required ordinary CI matrix

Use four explicit entries:

| OS runner | Expected `uname -m` | Rust target family |
| --- | --- | --- |
| `ubuntu-latest` | `x86_64` | Linux x86-64 |
| `ubuntu-24.04-arm` | `aarch64` | Linux ARM64 |
| `macos-15-intel` | `x86_64` | macOS Intel |
| `macos-15` | `arm64` | macOS Apple Silicon |

If GitHub changes a runner label, use the current documented native label and update the plan index/status with the exact replacement. Do not replace a native lane with QEMU.

Each lane must run:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-targets --all-features
cargo doc --workspace --no-deps
```

Platform-specific smoke tests must also run:

- Linux lanes: native Linux collector tests;
- macOS lanes: native macOS FFI collector tests.

Format and docs may be deduplicated into one lane only if the per-architecture lanes still run compilation, Clippy, all-target tests, and native smoke. The simplest acceptable implementation is to keep the current full gate in every lane.

## Architecture verification

Keep an explicit architecture check before compilation.

The diagnostic must print:

```text
runner OS
uname -m
rustc -vV
cargo -V
```

Fail immediately when the observed architecture differs from the matrix entry.

Do not normalize Linux `aarch64` to macOS `arm64` silently; store the expected native spelling per runner.

## Cache correction

Change cache keys so architecture and toolchain are included. Example:

```yaml
key: ${{ runner.os }}-${{ matrix.expected_arch }}-${{ matrix.toolchain }}-cargo-${{ hashFiles('**/Cargo.lock') }}
```

Restore keys must not cross architectures.

Acceptable restore prefix:

```yaml
restore-keys: |
  ${{ runner.os }}-${{ matrix.expected_arch }}-${{ matrix.toolchain }}-cargo-
```

Do not restore a `macOS-x86_64` target cache into `macOS-arm64`, or Linux x86-64 into Linux ARM64.

It is acceptable to cache only registry/git directories and stop caching `target` if that produces more reliable native CI.

## MSRV matrix

Expand the Rust 1.75 check to all four native runners.

Minimum command:

```bash
cargo check --workspace --all-targets --all-features
```

Preferred command, when time is acceptable:

```bash
cargo test --workspace --all-targets --all-features --no-run
```

The MSRV matrix must:

- verify architecture;
- install exactly Rust `1.75`;
- avoid stable-only formatter/Clippy behavior if components are unavailable for that historical toolchain;
- compile target-specific collector, service, and client code;
- use architecture-specific cache keys;
- fail on dependency resolution that raises the effective MSRV.

If a transitive dependency no longer resolves under Rust 1.75, fix dependency selection or lockfile policy. Do not silently change `rust-version` to a newer value in this phase.

## Linux ARM64-specific checks

The Linux ARM64 lane must execute, not merely compile:

- procfs/sysfs fixture tests;
- native Linux collector smoke;
- daemon sampler/server tests;
- client polling/state tests;
- packaging script syntax tests where applicable.

Add an assertion that `std::env::consts::ARCH` and `uname -m` represent the expected ARM64 target in the native smoke evidence.

## macOS-specific checks

Both macOS lanes must execute:

- Mach FFI native smoke;
- high-bit conversion unit tests from Phase 23;
- sampler reset/recovery tests from Phase 24;
- plist syntax/static packaging tests where available.

Do not allow the Intel lane to be replaced by Rosetta execution on an ARM runner. `uname -m` must be `x86_64`.

## Workflow validation tests

Extend the repository’s workflow validator or add a narrow CI matrix test that rejects:

1. missing Linux ARM64 ordinary lane;
2. missing macOS Intel lane;
3. missing macOS ARM64 lane;
4. duplicate architecture entries;
5. cache keys without architecture;
6. MSRV matrix missing a supported architecture;
7. architecture check absent or mismatched.

Do not use text-only assertions when parsed YAML matrix inspection is already available from Phase 21.

## Smaller-model implementation sequence

1. Add a failing validator test for the missing Linux ARM64 lane.
2. Add the `ubuntu-24.04-arm` stable matrix entry.
3. correct architecture-specific cache keys.
4. run the Linux native smoke on both Linux lanes.
5. convert the MSRV job into a four-entry matrix.
6. add architecture verification to MSRV.
7. add workflow matrix tests.
8. update supported-target documentation.
9. push and observe all four stable lanes.
10. observe all four MSRV lanes.
11. fix only genuine portability/MSRV defects exposed by those lanes.

## Guardrails

- Do not use cross-compilation as qualifying evidence.
- Do not remove Intel macOS support.
- Do not make Linux ARM64 release-only.
- Do not add `continue-on-error` to a native lane.
- Do not skip tests on ARM64 merely for runtime cost.
- Do not share `target` cache keys across architectures.
- Do not raise MSRV to resolve a dependency without a separate approved decision.
- Do not accept a runner whose observed architecture differs from the matrix declaration.

## Validation commands

Local workflow and release-tooling checks:

```bash
python3 -m unittest discover -s scripts -p 'test*.py'
```

Local workspace gate:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-targets --all-features
cargo doc --workspace --no-deps
```

CI must provide native results for all matrix entries.

## Acceptance criteria

Phase 27 is complete only when all criteria are demonstrated:

1. Ordinary CI contains Linux x86-64, Linux ARM64, macOS Intel, and macOS ARM64 lanes.
2. Every lane verifies the observed native architecture.
3. Every lane runs workspace Clippy and all-target/all-feature tests.
4. Linux ARM64 executes the native Linux collector smoke.
5. Both macOS lanes execute the native Mach FFI smoke.
6. Cache keys include architecture and toolchain, or `target` caching is removed.
7. No restore key crosses architecture boundaries.
8. Rust 1.75 compilation is checked on all four native architectures.
9. Target-specific code compiles under Rust 1.75.
10. Workflow validation rejects omission of any supported architecture.
11. No native lane is allowed to fail or continue on error.
12. CI is green on all four stable lanes for the same commit SHA.
13. CI is green on all four MSRV lanes for the same commit SHA.
14. Run IDs and job names are recorded for final evidence.
15. Supported-target documentation matches the executable matrix.

- observed architecture from each lane;
- stable CI run ID and job conclusions;
- MSRV run ID and job conclusions;
